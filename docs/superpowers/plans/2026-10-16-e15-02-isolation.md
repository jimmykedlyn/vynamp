# TASK-E15-02 — Worktrees, claims e handoff Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Comprovar isolamento e exclusividade local e impedir remoção quando a claim não representa a worktree real.

**Architecture:** Manter CLI e claims no common Git dir (`auralis/claims`). Usar fixtures com Git real para observar arquivos, índices, refs e claims; validar identidade/branch/HEAD antes de qualquer remoção. Sem novo mecanismo de transferência automática de owner.

**Tech Stack:** Rust 1.99.0, Git, cargo xtask, testes de integração existentes.

**Spec:** [Worktrees](../../engineering/02-worktrees.md), [TASK-E15-02](../../../tasks/items/TASK-E15-02.md), REQ-E15-02, ADR-007. QA-009/QA-012 aplicados somente a entradas adversariais e preservação/recuperação do tooling; não certificam plugins/updater do produto.

## Global Constraints

- Um owner por TASK; claim local não coordena máquinas diferentes.
- Reutilizar worktree E15-02/branch/claim existentes, base `389381cd6bec7442737bd632badb01de917215b2`.
- Sem `--force`, bypass de hooks, remoção automática de claims antigas ou edição de worktrees Claude.
- Hotfix só remove após integração em main e develop; outras branches em develop.
- `application_ready`, `release_enabled`, `branding_exports_ready` permanecem false.
- Execução inline autorizada pelo painel; revisão técnica final é Claude em sessão/worktree separada. Não reabrir decisão já dada.

## Review Focus

1. Duas criações simultâneas da mesma TASK elegem apenas um owner e não apagam a claim vencedora.
2. Claim antiga após checkout/detach não permite descartar HEAD não integrado.
3. Metadados inconsistentes ou path de outro repositório não autorizam remoção.
4. Falha de criação preserva destino existente e permite retry sem roubar claim.
5. Hotfix integrado só em uma das bases permanece; remoção bem-sucedida limpa apenas seus próprios recursos.
