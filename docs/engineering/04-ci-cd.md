# CI/CD e gates por plataforma

Versão 0.7.0 · 2026-10-19 · Configuração do projeto; player ainda não implementado.

CI/CD somente pelo Woodpecker ([ADR-010](../architecture/adr/ADR-010-woodpecker-only-ci.md)); GitHub Actions removido e recusado por `cargo xtask check-delivery`. Servidor local + agentes Linux/Docker e Windows nativo, exposto só por Cloudflare Tunnel em `ci-cd-vynamp.jkca.lat` (HTTP; gRPC local). Workflows em .woodpecker: linux, windows, android, gate, release. Imagens Docker pinadas por tag + digest; Windows Local usa pwsh do host. Repo privado, não trusted, sem `privileged`/`volumes`; PR de fork exige aprovação e nunca roda sem revisão no agente Windows. Dependabot propõe updates Cargo semanais. Operação: [infra/ci/woodpecker](../../infra/ci/woodpecker/README.md) · evidências: [task-e15-04](../evidence/PR/task-e15-04/README.md).

CI PR/push/manual: documentação/schema/backlog/delivery/fmt/clippy/tests tooling e `cargo test --workspace` nos agentes Linux e Windows, independentemente do app. Fontes reais em apps/desktop ativam core em `x86_64-unknown-linux-gnu` e `x86_64-pc-windows-msvc`; Gradle real ativa Android unit/lint/debug no agente Linux. macOS Intel/Apple Silicon: não verificados até existir agente Mac. Toolchains/locks obrigatórios a partir de código real. O workflow `gate` é publicado como status `CI Gate` e só roda quando linux, windows e android tiveram sucesso; falha/cancelamento/agente ausente nunca viram success. Pipelines PowerShell ativam `$PSNativeCommandUseErrorActionPreference` e pipelines sh não usam pipe em comandos verificados, para não mascarar falha. Nesta fase o Cargo workspace contém somente xtask; sem fontes desktop/Gradle reais, skips declarados não significam que player passou testes.

Release em tag v*: preflight exige implementation/release flags, Cargo/Gradle/locks/licença/notices/public key, evidência completa dos cinco alvos, digest de source revisado e tag `v<versão>` (`CI_COMMIT_TAG`). A pipeline termina em falha depois do preflight: builders Windows/Linux/macOSUniversal/Android, transporte de artifacts entre agentes, secrets de signing e draft privado ainda não foram migrados para o Woodpecker. Ao migrar: conjunto completo/não vazio, hashes, manifesto assinado, apenas draft; só mantenedor publica após verificação. Não distribuir chave privada em artifacts/logs.

Hardware sem workflow: `cargo xtask quality-gate` em máquinas confiáveis com Windows/Linux/MacIntel/MacSilicon/Androiddevice, a partir de main/develop. Depende de tests/hardware/Cargo.toml e harness Rust reais, sem auto-green caso harness/aplicativo faltem; agentes de hardware pertencem à TASK-E15-05. Process death/a11y/soak/bit-perfect não são aprovados pelo CI de build. Fuzz, numerical regressions, update/install drills e perf são detalhados em testes; precisam de harness conforme M1–M3.

Rust 1.99.0 foi instalado e pinado; config/toolchains.json mantém NDK/SDK como decisões M0 pendentes e CI de código falha se não preenchidas. Versões/digests em [versions.json](../../infra/ci/woodpecker/versions.json) devem ser auditadas antes release e atualizadas por PR. [Woodpecker docs](https://woodpecker-ci.org/docs/intro).

CD web M4: implementar IaC/healthcheck/migrations expand-contract, staging e environment production separado; não publicar infraestrutura vazia ou usar credentials mobile para backend. TASK-E11-10/E09 continuam donos dessa entrega.
