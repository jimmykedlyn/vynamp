# Ativação externa, lotes, IPC e ownership de perfil

Versão 0.7.0 · Contrato compartilhado por adapters; nenhuma implementação de app neste pacote.

## Entrada comum

[OpenRequest](../../schemas/open-request.schema.json) é envelope interno versionado: request_id UUID, origin informativa, action open/enqueue, profile_id, entries ordenadas e access_ref opaco. Origem/flags vindas de outro processo não concedem privilégios; broker confere peer e grants reais. ACK accepted/rejected correlaciona request_id e generation; accepted significa comando enfileirado, não áudio já emitido. Não serializar bearer, senha, descriptor FD numérico arbitrário ou filesystem permissions fornecidos pelo cliente. Transferência de FD usa transporte nativo autorizado, vinculada ao grant, lifetime e peer.

CLI planejada M1–M3: vynamp --open -- <locator...>, --enqueue -- <locator...>, --profile <id> e subcomandos control allowlisted. Terminador -- é obrigatório nos comandos gerados; arquivo -song.flac não vira flag. No Windows usar UTF-16/native argv e APIs corretas, Unix argv separado; não shell -c/cmd /c, expansão de ambiente ou execução de metadados. file URI com %/#/? é decodificado pela regra do URI, sem dupla decodificação. Uma extensão errada pode abrir por probe; sem extensão não é execução. Pasta só com opção explícita, scan cancelável e sem seguir symlinks/ciclos por padrão.

Limites: envelope ≤1 MiB antes de parse/alocação, 1–10000 entries, locator ≤8192 bytes UTF-8, profundidade playlist≤8/10000 itens após expansão; totais menores por plataforma quando documentados. JSON Schema maxLength limita caracteres Unicode, não bytes: transporte/broker valida adicionalmente comprimento UTF-8 e envelope; testar entrada multibyte que passe o schema e exceda bytes. Na UI, resolver assíncrono cancelável; nenhum parser/I/O na callback. Não confiar no MIME do sender. Playlists locais resolvem relativos contra a origem concedida; grant Android/Mac de playlist não autoriza irmãos. Playlist remota nunca abre file/content do cliente e cada filho passa política de rede. .m3u8 reconhece conteúdo HLS versus playlist local sem presumir por extensão; CUE abre faixas virtuais do asset, não executa comandos.

## Semântica determinística

Open: resolver/probar lote, apresentar erros individuais; se houver itens válidos, substituir a fila ativa uma única vez pela lista válida na ordem recebida e tocar o primeiro elegível. Lote completamente inválido/cancelado preserva fila/reprodução. Não sobrescrever playlist salva nem indexar biblioteca automaticamente. Erro de grant/DRM/codec não causa descarte de itens persistidos. Antes do commit, nova solicitação/cancel gera generation e impede resolver antigo de alterar fila.

Enqueue: adicionar válidos em ordem, sem interromper fonte, seek, shuffle corrente ou iniciar áudio espontaneamente se parado. Próxima faixa é outra ação, não sinônimo de enqueue. Duplicatas intencionais são preservadas; idempotência elimina somente reentrega do mesmo request_id/conteúdo (mesmo ID com payload diferente é Conflict). Receipt de request_id + hash do payload + resultado/generation é persistido atomicamente com o commit da fila; crash após commit e antes ACK permite consultar receipt/repetir o mesmo ACK, sem novo enqueue. Não persistir tokens/grants no receipt. Retenção mínima de 5 minutos, capacidade 1024 receipts; enquanto entradas não expirarem, rejeitar novos pedidos com Busy em vez de evictar receipts válidos. Após restart, recuperar receipts e fila juntos; não prometer que o áudio já foi emitido. Expiração encerra a garantia: cliente com resultado indeterminado consulta fila/mostra confirmação antes de enviar nova ação, sem retry automático de enqueue. Falha anterior ao commit pode repetir o mesmo ID dentro da janela. Solicitações diferentes não são fundidas sem ID de lote/protocolo demonstrado.

Open With/duplo clique por padrão Open; Android Share por padrão preview para escolher Open/Enqueue. Configuração do usuário pode trocar default de ativação, mas não permite esconder efeitos destrutivos em biblioteca ou source. Background activation não rouba foco da janela por padrão se OS/pref impedem; desktop pode sinalizar tarefa, Android respeita lifecycle/focus. Estado pending/erro é acessível e localizável.

## Um owner por perfil

Um owner pela identidade canônica do armazenamento do perfil é regra para escrita/playback, atravessando sessões do mesmo usuário. Resolver aliases/symlinks e identidade do diretório/volume antes do lock; sessão só delimita IPC/foco. Se outra sessão não puder encaminhar ao owner existente, mostrar ProfileInUse; nunca iniciar segundo writer. Lock interprocesso OS precede abrir DB/config/jobs/migrations/queue; arquivo de lock contém metadata diagnóstica, não é prova de ownership sem lock real. Demais launches encaminham via IPC ao owner e terminam após ACK ou mostram erro/timeout; nunca iniciam uma engine concorrente por arquivo.

Múltiplas instâncias explícitas exigem perfis separados, DB/cache/config/queue/jobs próprios e escolha de dispositivo/focus; perfil read-only pode inspecionar sem mutar nem tocar por padrão. Installed+portable apontando para o mesmo perfil obedece mesmo lock, mesmo se binários/caminhos diferentes. Não permitir dois SQL writers só porque cada processo tem seu write actor. Migrations/update aguardam owner encerrar sob escolha do usuário; não matar playback/gravação para migrar.

Windows named pipe com ACL por usuário e validação de peer/session. Unix domain socket no XDG_RUNTIME_DIR privado/permissão 0600, peer credentials e path/collision guards; Mac runtime privado equivalente. Idempotência, quotas e versão compatível; request vindo de usuário diferente ou volume excessivo é rejeitado. Sem fallback para pipe TCP/LAN sem autenticação. O serviço Android é owner, Activity é adapter; grants pertencem ao processo/serviço realmente autorizado, não à view recriada.

Crash libera lock OS; stale metadata só é removida após provar ausência de owner; PID isolado pode ser reutilizado e não prova seguro. Launch race testa uma eleição, sem duas engines; timeout padrão 5 s com cancel/retry, sem reset automático de perfil. Se versão de IPC major incompatível, explicar e pedir fechar/usar outro perfil, sem escrever DB novo por baixo.

## Portable, backup e consentimento

Modo instalado usa diretórios OS por usuário; portable explícito usa perfil designado e caminho estável, sem registrar defaults/startup por surpresa. Pasta read-only oferece perfil externo ou sessão volátil com aviso de que não persistirá; não copiar credenciais em plaintext para USB. Vault indisponível mantém sessão sem persistência ou opção segura do usuário. Import/export config/presets/playlist/library backup são versionados, validados e redacted; nunca exportar tokens/grants/paths privados sem seleção.

Backup consistente sob owner com transação/checkpoint; restore por staging+hash/schema, preview de conflitos, rollback e sem apagar mídia. Paths relocados rebind por identidade/grant com confirmação quando necessário; identidade não é simples índice de dispositivo nem só nome de arquivo. Config/plugin version incompatível leva recovery/safe mode, não criação silenciosa de perfil vazio substituindo o antigo.

## Deep links M4

vynamp scheme próprio e HTTPS app links só com domínio real verificado, routes/IDs versionados allowlisted. OAuth callback verifica state/PKCE antes trocar código. Website link nunca concede file/content/path/shell/install-plugin/autoplay arbitrários; primeiro mostra item/conta/ação e pede intenção quando inicia playback externo. Não registrar handler global HTTP/HTTPS nem abrir query URL privada em logs. Autenticação/rights seguem provider; deeplink não é acesso à fila como API geral.

Gate QA-023/024/031 nos cenários aplicáveis M1–M3; deep links/OAuth são M4. Testar também owner entre sessões/aliases e commit→crash→retry. Demais cenários: cold/warm/20 launches simultâneos, 1/2/20/100 itens, invalid-only/mixed, duplicatas, Unicode/metacaracteres/leading-, kill/retry, same-ID conflict, installed+portable/profile read-only, IPCmajor, DBmigration bloqueada, Android grants/rotation, Finder callbacks antes bootstrap. Registrar estado/ordem/frameclock/erro e preservar source.
