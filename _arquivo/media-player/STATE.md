## 2026-11-11 — o hook do umbrella e o bit de execucao que faltava

- **A lacuna que estava aberta era maior do que eu tinha reportado.** Eu disse que faltava "instrucao de instalacao" do hook no umbrella. Faltava o `setup.sh` inteiro — e, ao escreve-lo, medi o indice e achei um segundo defeito atras do primeiro: **os dois hooks do umbrella estavam comitados como `100644`**, enquanto os dos oito modulos estavam `100755`. Em Linux e macOS o git **pula hook sem bit de execucao, em silencio**; aqui no Windows o Git Bash executa assim mesmo, entao isso nunca apareceria nesta maquina. So num clone de outra pessoa, ou num runner que rode o hook.
- **O commit `4be812b` (PR #46) fechou as duas coisas:** `setup.sh` novo no umbrella e `git update-index --chmod=+x` nos dois hooks, que agora constam como `100755` no `develop`. `CONTRIBUTING.md` e `README.md` passam a instruir `sh setup.sh` uma vez por clone, nos dois idiomas.
- **Provado num clone descartavel, nao por leitura.** Clone raso de `develop` em `/tmp`: antes do script `core.hooksPath` vinha vazio; depois, `.githooks`. Commit em `develop` foi **barrado** ("Commit blocked on main/develop/detached HEAD"). Removi o `core.hooksPath` e o mesmo commit **passou** — prova de que e o script que fecha a lacuna, e nao outra coisa. Clone apagado depois.
- **Um bug meu, pego no teste.** A primeira versao do script dizia "`.githooks/pre-push` nao tem bit de execucao" quando o arquivo nem existia. Corrigido com um teste `-f` antes. Foram quatro casos medidos: bits em `644` (viram `755`), CRLF (avisa), hook ausente (avisa), tudo certo (silencioso, exit 0).
- **A deteccao de CRLF nao usa `grep` nem `awk`, e isso foi medido.** Neste ambiente os dois tratam o CR como terminador de linha e respondem que nao ha nada, num arquivo com CRLF confirmado por `od -c`. A checagem compara `tr -d '
' | wc -c` com `wc -c` — `tr` acerta, `grep` e `awk` nao.
- **O laco dos submodulos abortava no decimo caminho.** `git submodule foreach 'sh setup.sh'` percorre nove caminhos: os oito modulos e o `reference/vynamp-mvp`, que e o pacote JavaScript congelado, sem `setup.sh` e sem `.githooks`. O laco ligava os oito e entao falhava no nono, com exit de erro — lido como "nao funcionou" quando tinha funcionado para tudo que importava. O PR #47 documenta a forma que funciona (`if [ -f setup.sh ]`), medida com oito `ok` e exit 0.
- **Os oito modulos nao precisaram de mudanca.** Medi: `setup.sh` de 536 B, `100755` nos oito, e cada um tem `.gitattributes` com `.githooks/** text eol=lf` — a protecao contra CRLF que o umbrella resolve pelo `* text=auto eol=lf` global.
